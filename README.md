# Prompt Engineering Academy

Интерактивный образовательный портал по prompt engineering для пользователей с базовым опытом работы с AI. Теория в шести статьях соединяется с упражнениями внутри текста, а итоговый тест проверяет понимание и применение знаний.

## Статус

Локальная реализация подготовлена к сдаче. После первоначальной приёмки исправлены проверки отрицаний, равнозначных ограничений и исходных данных симулятора; добавлены проверки этих случаев. Портал содержит шесть статей, десять типов упражнений, итоговый тест и сохранение прогресса в браузере.

Актуальные результаты подготовки, состав файлов и сверка с исходным заданием приведены в [проверке перед сдачей](docs/SUBMISSION_CHECK.md). [Приёмка от 10 октября](docs/FINAL_ACCEPTANCE.md) сохраняет исторические результаты и карту требований. Репозиторий проекта: [prompt-engineering-academy](https://github.com/WebRazrabotchikAlexanderAkk/prompt-engineering-academy). Параметры публикации сайта утверждены в `DEC-036`; внешний выпуск требует отдельного запроса.

## Подтверждённый MVP

- Astro + React + TypeScript.
- Шесть русскоязычных учебных статей.
- 18 inline-упражнений.
- 10 типов упражнений, включая `ContextBudget`.
- Банк из 24 заданий и итоговая выборка из 12.
- Первичный и финальный результаты после одной корректирующей попытки.
- Локальное сохранение прогресса.
- Светлая и тёмная темы.
- XP, достижения, награды и итоговые ранги.
- Доступность – применимые критерии WCAG 2.2 AA, клавиатурное управление и интерфейс от 360 px проверены в согласованном локальном объёме. Это не независимая сертификация и не проверка физического сенсорного устройства или реальной программы чтения экрана.
- Публичный репозиторий `prompt-engineering-academy` и GitHub Pages на этапе публикации.

## Структура продукта

- Главная страница объединяет учебный маршрут и каталог шести статей.
- Каждая статья является отдельной учебной миссией.
- Итоговый тест доступен сразу, но интерфейс рекомендует проходить статьи последовательно.
- Экран результата входит в страницу теста.
- Страница «О проекте» кратко объясняет назначение портала.

## Почему я выбрал эти технологии

Для проекта я выбрал Astro, потому что хотел попробовать эту технологию на практике. Для упражнений и итогового теста использовал React, чтобы переиспользовать компоненты и работать с ответами пользователя. TypeScript помог описать структуру заданий и результатов и находить ошибки в работе с данными ещё во время разработки.

## Визуальная и CSS-архитектура

Утверждена зелёно-фиолетовая кибернетическая визуальная система. Цветовые и типографические переменные находятся в `src/styles/tokens.css`, общие правила – в `src/styles/global.css`. Astro-компоненты используют scoped `<style>`, React-компоненты – CSS Modules рядом с компонентом. Дополнительные библиотеки оформления в MVP не используются.

## Локальный запуск

Для полного набора разработки и тестирования рекомендуется Node.js 24.15.0 или новее в ветке 24.x и npm не ниже 9.6.5. Также допустимы Node.js 22.22.2–22.x или версии от 26.0.0; точный контракт указан в `package.json`. Нижний предел учитывает не только Astro, но и `jsdom` для компонентных проверок. Для браузерных проверок нужен установленный Microsoft Edge. Текущая проверенная среда: Node.js 24.16.0 и npm 11.13.0. Из каталога проекта:

Скачайте проект через GitHub кнопкой **Code → Download ZIP**, распакуйте архив и откройте терминал в папке с `package.json`. Либо используйте Git:

```sh
git clone https://github.com/WebRazrabotchikAlexanderAkk/prompt-engineering-academy.git
cd prompt-engineering-academy
```

После получения исходников установите зависимости и запустите портал:

```sh
npm ci
npm run dev
```

Откройте `http://127.0.0.1:4321/`. Главная содержит маршрут из шести статей; в каждой статье есть три упражнения. Итоговый тест доступен по `/quiz/`. Прогресс хранится только в этом браузере. Сброс прогресса на главной не должен менять тему.

Как попробовать: на главной нажмите «Начать обучение», прочитайте первую статью и ответьте на встроенный вопрос. После неверного ответа появится краткая подсказка и одна возможность исправить ответ; после окончательной отправки откроется разбор. Вернитесь на главную и откройте «Итоговый тест». Он выбирает 12 заданий: пройдите первый круг, затем исправьте ответы или завершите без остальных исправлений. Только на финальном экране откроются первый и окончательный баллы, ранг и рекомендация. Каждый пропущенный вопрос даёт ноль баллов.

Чтобы проверить готовые статические файлы локально, выполните `npm run build`, затем `npm run preview` и откройте адрес, показанный командой предпросмотра. Предпросмотр не публикует сайт.

Сервер разработки останавливается сочетанием `Ctrl+C` в его терминале. Если предпросмотр сообщает о запуске в фоне, остановите его командой `npm run preview -- stop` из той же папки проекта.

Команды проверок:

```sh
npm run typecheck
npm test -- --maxWorkers=1
npm run build
npm run test:e2e -- --project=edge --workers=1
npm run test:links
npm run check:links
npm run test:static
npm run check:static
npm run test:static-browser
```

Команда `test:e2e` автоматически запускает локальный сервер на `127.0.0.1:4322`, по умолчанию выбирает Microsoft Edge и останавливает только запущенный ею сервер. Команда `test:static-browser` аналогично запускает готовую сборку на `127.0.0.1:4323`. Если требуемый порт занят, сценарий завершится ошибкой вместо проверки другого сайта. Другие браузеры не входят в обязательную приёмку MVP. Проверка защиты от повторного сбоя также запускает проверку типов и сборку при работающем сервере. Сборка создаёт статические файлы в `dist`; это не публикация сайта.

`test:links` проверяет средство проверки ссылок без сети. `check:links` читает публичные HTTPS-источники из статей и выводит статусы и перенаправления; нужен доступ к сети. Код завершения 0 означает успешные ответы всех источников; 1 означает отсутствующий источник либо неподтверждённую доступность (например, сетевой запрет или тайм-аут). Эта команда не входит в обычный набор тестов, не проверяет внутренние ссылки, содержимое страниц или опубликованный сайт. Протокол: [LINK_CHECK.md](docs/LINK_CHECK.md).

## Устройство реализации

`test:static` проверяет разрешение путей средства проверки сборки. `check:static` создаёт две локальные сборки (корень `/` и тестовый префикс `/acceptance-preview/`) в игнорируемой папке `.astro/static-checks/run-*`, затем проверяет девять страниц, локальные ссылки и якоря, адреса ресурсов HTML и React-островов, CSS `url()` и строковые относительные ссылки на JS-модули. Требуется установленный набор зависимостей. Код завершения 0 означает отсутствие найденных ошибок. Сборки оставляются для осмотра; это не публикация и не выбор окончательного адреса сайта. Создавать их на другом диске нельзя из-за переноса промежуточных файлов Astro через `rename`. Проверка не исполняет JavaScript, не проверяет динамически составленные адреса, `srcset` или HTTP-настройки хостинга.

`src/domain` содержит типы, чистые функции оценки, выборку теста и награды. `src/components/exercises` содержит общую оболочку упражнения, редакторы ответов и обратную связь. `src/islands` связывает интерактивные компоненты с состоянием; `src/storage` отвечает за локальное сохранение. Статьи находятся в `src/content`, задания в `src/data`, страницы в `src/pages`.

Один контракт задания передаёт определение, редактор ответа и функцию оценки общей оболочке. Встроенное упражнение сохраняет свой результат автономно; тест использует те же редакторы и оценивание в общей последовательности. Десять типов: `MultipleChoice`, `MatchPairs`, `FillTheBlank`, `TrueFalse`, `OrderSteps`, `CaseStudy`, `PromptSimulator`, `SpotTheHallucination`, `PromptBuilder` и `ContextBudget`. Текстовые задания используют заранее заданные критерии и ответы, а не запросы к настоящей модели.

Собственный тип `ContextBudget` учит выбирать полезные сведения при ограниченной ёмкости контекста. У каждого фрагмента есть учебная стоимость и полезность. Нужно сохранить важные данные и уложиться в бюджет, исключив отвлекающие сведения. В статье «Токены и лимиты контекста» можно выбрать статус заказа, дату доставки и правило ответа; несвязанная история магазина расходует бюджет и ухудшает результат. Стоимости учебные и не являются подсчётом токенов настоящей модели.

Оценка упражнений лежит в диапазоне от 0 до 1; частично выполненные критерии дают частичный балл. Текстовые задания распознают перечисленные в данных формулировки и отрицания. В симуляторе заранее подготовленный ответ зависит от достигнутого уровня. В итоговом тесте оба результата и подробные объяснения открываются после завершения. Исторические баллы сохраняются при изменении правил; незавершённая попытка со старой версией требует перезапуска.

## Браузерная проверка готовой сборки

`npm run test:static-browser` заново собирает сайт с тестовым префиксом `/acceptance-preview/`, запускает локальный предпросмотр на `127.0.0.1:4323` и проверяет его в установленном Microsoft Edge. Проверяются девять страниц, загрузка ресурсов, значок вкладки, ответ/исправление упражнения, перезагрузка и сохранение темы, завершение теста через пропуски и переход по рекомендации. Проверка не использует пользовательский прогресс; временная сборка остаётся в `.astro/static-checks/browser-*`, проверочный сценарий сам управляет своим сервером. Это не проверка реального GitHub Pages и не разрешение публикации.

Оформление, организация стилей, перетаскивание и модель наград утверждены; выбранная тема сохраняется при сбросе учебного прогресса. Актуальные решения ведутся в [журнале решений](docs/DECISIONS.md). Параметры размещения утверждены; фактическая публикация требует отдельного прямого запроса.

## Ограничения
