# Требования Prompt Engineering Academy

Статус: утверждённые требования к MVP. Дата фиксации: 2026-08-07.

## Правила документа

- `MUST` — обязательное требование MVP.
- `SHOULD` — подтверждённая рекомендация качества; отклонение допустимо, если оно явно обосновано и не нарушает MUST.
- `OPEN` — подтверждённая область, детали которой требуют отдельного решения до реализации.
- Возможные улучшения не являются требованиями и перечислены отдельно.
- В столбце «Проверка» указан воспроизводимый способ приёмки.

| CORE-003 | MUST | Технологический стек — Astro + React + TypeScript. | Production build содержит Astro-проект, React-интеграцию и TypeScript typecheck без ошибок. |
| CORE-004 | MUST | Результат публикуется из публичного репозитория `prompt-engineering-academy` на GitHub Pages. | Открыть публичный репозиторий и опубликованный URL; пройти smoke-сценарий на опубликованной сборке. |

## 3. Контент

| ID | Уровень | Требование | Проверка |
|---|---|---|---|
| CNT-001 | MUST | Созданы шесть отдельных статей: работа LLM; галлюцинации; структура эффективного промпта; роль, контекст и ограничения; токены и лимиты контекста; безопасность AI. | Content validation находит ровно шесть обязательных slug и заголовков. |
| CNT-002 | MUST | Каждая статья содержит 800–1200 слов и рассчитана примерно на 7–10 минут чтения. | Скрипт подсчёта слов выдаёт значение в диапазоне для каждой MDX-статьи. |
| CNT-003 | MUST | В каждой статье органично размещено три inline-упражнения; всего 18. | MDX validation подтверждает ровно три уникальных exercise ID на статью и 18 в сумме. |
| CNT-004 | MUST | Статья считается пройденной после попытки выполнить все три упражнения; ошибка не блокирует чтение. | E2E: дать неправильный ответ, продолжить чтение, выполнить остальные задания и получить статус завершения статьи. |
| CNT-005 | MUST | Возле важных фактических утверждений размещены прямые ссылки на источники. | Content review и link checker подтверждают наличие ссылки рядом с отмеченным фактическим утверждением и успешный HTTP-ответ источника. |
| CNT-006 | MUST | Используются лёгкие SVG/CSS-иллюстрации для структуры промпта, контекстного окна и статусов; большая библиотека изображений не требуется. | Asset inventory содержит предусмотренные схемы и не содержит необоснованного набора тяжёлых растровых файлов. |

## 4. Система упражнений

| ID | Уровень | Требование | Проверка |
|---|---|---|---|
| EX-001 | MUST | Реализованы пять базовых типов: MultipleChoice, MatchPairs, FillTheBlank, TrueFalse, OrderSteps. | Component registry и component tests находят и успешно отображают каждый тип. |
| EX-002 | MUST | Реализованы четыре продвинутых типа: CaseStudy, PromptSimulator, SpotTheHallucination, PromptBuilder. | Component registry и component tests находят и успешно отображают каждый тип. |
| EX-003 | MUST | Реализован кастомный ContextBudget. | Component test проверяет лимит, полезные фрагменты, distractors и переполнение бюджета. |
| EX-004 | MUST | Одна библиотека компонентов работает в автономном inline-режиме и в агрегированном quiz-режиме. | Для каждого типа component test запускает обе оболочки с одной definition и сравнивает совместимый result contract. |
| EX-005 | MUST | Компоненты поддерживают состояния: не отвечено, введён ответ, верно, частично верно, неверно и корректирующая попытка, если она разрешена. | State-transition tests проверяют все применимые состояния и запрещённые переходы. |
| EX-006 | MUST | Drag-and-drop задания имеют кнопочную, клавиатурную и touch-friendly альтернативу. | E2E выполняет MatchPairs и OrderSteps без drag gesture; keyboard-only прогон не теряет функциональность. |
| EX-007 | MUST | CaseStudy оценивается детерминированной сценарной рубрикой без AI. | Одинаковый ввод дважды даёт одинаковый балл и breakdown критериев без network request. |
| EX-008 | MUST | PromptSimulator выбирает подготовленный реалистичный ответ по детерминированной оценке промпта. | Fixture tests связывают слабый, частичный и качественный prompt с ожидаемыми подготовленными response tier. |

## 5. Итоговый тест и оценивание

| ID | Уровень | Требование | Проверка |
|---|---|---|---|
| QUIZ-001 | MUST | Банк содержит 24 задания: по четыре на каждую из шести тем. | Data validation подтверждает 24 уникальных ID и распределение 4×6. |
| QUIZ-002 | MUST | Попытка выбирает 12 заданий: по два на тему, минимум семь типов, минимум два продвинутых и минимум один ContextBudget. | Property tests на множестве seed подтверждают все ограничения выборки и отсутствие дубликатов. |
| QUIZ-003 | MUST | Порядок заданий и допустимых вариантов перемешивается; незавершённая попытка не меняется после reload. | E2E сохраняет ID и порядок до reload и сравнивает после; новая попытка с другим seed допускает другой порядок. |
| QUIZ-004 | SHOULD | Банк может использовать концепции inline-упражнений, но предпочтительно содержит адаптированные, а не дословные повторы; ориентир — 12 адаптаций и 12 новых задач. | Content review фиксирует фактическое соотношение; каждое дословное совпадение помечено и обосновано. Отклонение от 12/12 не блокирует релиз само по себе. |
| QUIZ-005 | MUST | Первое прохождение не показывает правильность отдельных ответов. После 12 ответов фиксируется первичный балл и показываются подсказки без готовых ответов. | E2E проверяет отсутствие correct/incorrect и answer key до завершения первой фазы, затем наличие первичного результата и hints. |
| QUIZ-006 | MUST | Разрешена одна корректирующая попытка для неверных и частичных ответов; после неё фиксируется финальный балл и показываются точные ответы и объяснения. | E2E подтверждает ровно один correction transition и невозможность второй коррекции в той же попытке. |
| QUIZ-007 | MUST | Прохождение определяется финальным результатом не ниже 70%; первичный и финальный результаты отображаются отдельно. | Boundary tests: 69.99% не пройдено, 70% пройдено; UI показывает оба значения. |
| QUIZ-008 | MUST | Итог содержит рекомендации по темам на основе ошибок. | Fixture с ошибками в двух темах выдаёт рекомендации именно по этим темам. |
| SCR-001 | MUST | Single-choice даёт 1 или 0. Multi-select: любой лишний вариант даёт 0; неполный набор только правильных вариантов даёт пропорциональный балл; полный балл требует точного набора. | Unit tests покрывают точный, неполный, лишний и полностью неверный ответы. |
| SCR-002 | MUST | MatchPairs и FillTheBlank дают частичный балл по элементам; TrueFalse бинарен; OrderSteps учитывает правильный относительный порядок. | Табличные unit tests проверяют нулевой, частичный и полный результаты каждого типа. |
| SCR-003 | MUST | FillTheBlank нормализует регистр, пробелы, `е/ё`, завершающую пунктуацию и явные синонимы; tolerance одной опечатки разрешается только настройкой конкретного длинного слова. | Unit tests для каждой нормализации и отрицательный тест для неразрешённой опечатки. |
| SCR-004 | MUST | SpotTheHallucination начисляет баллы за верные выделения, штрафует ложные и не опускается ниже нуля. | Unit tests проверяют true positives, false positives, mixed selection и lower bound. |
| SCR-005 | MUST | PromptBuilder оценивает блоки, категории и размещение; ContextBudget оценивает полезность под лимитом, distractors и превышение бюджета. | Unit tests проверяют частичный и полный PromptBuilder, оптимальный ContextBudget, distractor и over-budget=0. |

|---|---|---|---|

## Открытые решения, блокирующие отдельные части реализации

- `OPEN-ARCH-001`: буквальное наследование компонентов или React composition с общим контрактом. Рекомендована composition.
- `OPEN-UX-001`: палитра, типографика, карточки, иллюстративный стиль и интенсивность анимаций.
- `OPEN-UX-002`: plain CSS/CSS Modules или иной отдельно одобренный подход.
- `OPEN-DND-001`: библиотека или собственная реализация drag-and-drop.
- `OPEN-GAM-001`: формула XP, каталог достижений и конкретные награды.
- `OPEN-REL-001`: GitHub account, Pages base path и ручной/автоматический способ публикации.

|---|---|---|

## Возможные улучшения — не входят в MVP

- Custom domain и аналитика после отдельного одобрения.
- Полная история попыток вместо хранения только последнего и лучшего результатов.
- Любые аккаунты, синхронизация между устройствами, backend или настоящий AI — только как новый отдельно согласованный scope.
