# 01 — Experience, Visual System and Accessibility

## Назначение

Определить пользовательские потоки, visual system, styling architecture, состояния интерфейса, responsive и accessibility contract. Визуальное направление утверждено в `DEC-019`, организация стилей — в `DEC-021`.

## Experience principles

- Практика находится внутри учебного повествования, а не вынесена в конец статьи.
- Рекомендуемый маршрут заметен, но не создаёт locks.
- Ошибка воспринимается как обучающий сигнал, а не наказание.
- Игровые элементы помогают ориентироваться и не скрывают содержание.
- Состояние всегда выражается текстом/иконкой, а не только цветом.

## Главная страница

Обязательные зоны:

1. Название и краткое обещание продукта.
2. Общий прогресс упражнений: процент и «N из 18» по spec 04; отдельно XP summary.
3. Карта шести миссий в рекомендуемом порядке.
4. На каждой карточке: номер, тема, краткая цель, статус и переход.
5. Доступный переход к итоговому тесту.
6. Переключатель темы.

Карточки не блокируются. Незавершённая предыдущая миссия может быть отмечена рекомендацией, но не отключает ссылку.

## Страница статьи

- Читаемая колонка текста.
- Видимый заголовок, цель и прогресс статьи.
- Три упражнения после соответствующих смысловых блоков.
- Ссылки на источники рядом с утверждениями.
- Переходы к предыдущей/следующей миссии и главной.
- Статус завершения после первой принятой отправки каждого из трёх разных упражнений; пустая отправка не считается.
- При восстановлении завершённого встроенного упражнения пояснять, что сохранён результат, но прежний ввод не восстанавливается: пустые недоступные поля не означают потерю баллов. Это пояснение существующих правил хранения, не изменение состава сохраняемых данных.

## Страница теста

Состояния UI:

1. Introduction и запуск.
2. Primary answering.
3. Экран исправлений с минимальными подсказками, без первичного/финального балла и answer key (DEC-024).
4. Correction answering.
5. Final result, answer key и recommendations.

На странице теста обязательны визуальная полоса прогресса и текстовое описание. Они показывают продвижение по фазе, не баллы и не правильность.

- Первая фаза: полоса = число отправленных или явно пропущенных вопросов / 12. Подпись «Обработано N из 12»; позиция открытого вопроса показывается отдельно и не меняет заполнение полосы.
- Исправления: полоса = число принятых исправлений / число вопросов, доступных для исправления в начале фазы. Подпись «Исправлено M из K». Непринятая пустая отправка не увеличивает счётчик. K неизменно внутри фазы.
- При K=0 этап исправлений не открывается, показывается финальный результат. При досрочном завершении исправлений полоса заменяется итоговым экраном; не выдавать неисправленные вопросы за исправленные.
- Полоса имеет доступное название, минимум, максимум и текущее значение; текстовая подпись доступна без восприятия цвета. При reload восстановленные значения соответствуют сохранённой фазе и ответам.
- Это прогресс текущего теста, отдельный от общего прогресса 18 упражнений курса (spec 04).

## Exercise visual states

Каждый компонент предоставляет согласованные состояния:

- ready;
- edited;
- submitted;
- correct;
- partial;
- incorrect;
- hint available;
- correction;
- reviewed;
- disabled только когда transition запрещён.

Тексты labels должны быть понятны без знания внутреннего типа компонента.

## Утверждённое визуальное направление

Образ — защищённая учебная киберсистема: тёмное цифровое пространство, сеть данных, геометрический «контур защиты» и шесть связанных миссий. Тон взрослый и технологичный, но не агрессивный: без черепов, капюшонов, псевдотерминалов и декоративной перегрузки. Утверждённый Product Design mockup задаёт направление, а требования доступности и учебные сценарии имеют приоритет над буквальным повторением отдельных пикселей.

Роли основных цветов неизменны:

- зелёный — primary action, текущая/завершённая миссия, progress и success;
- фиолетовый — структура сети, info, глубина и доступные, но ещё не завершённые элементы;
- warning и error используют отдельные semantic colors;
- ни один status не передаётся только цветом.

## Темы и palette tokens

Обязательны светлая и тёмная темы и сохранение выбора. Общий reset учебного прогресса не меняет theme preference (`DEC-020`). Тёмная тема является эталонным воплощением выбранного mockup; светлая — семантический remap, а не простая инверсия.

Эти значения не заменяют итоговый contrast audit фактических компонентов.

## Styling architecture

- `src/styles/tokens.css` — единственный владелец palette literals, semantic custom properties, theme mappings, spacing и motion tokens.
- `src/styles/global.css` — reset, `@font-face`, базовые `html/body`, typography, visible focus и общие правила для MDX article content. Корневой Astro layout является единственной точкой global imports и импортирует `tokens.css` и `global.css` ровно по одному разу.
- `.astro`-компоненты используют нативный scoped `<style>`. `is:global` не применяется для component styling; действительно общие правила переносятся в `global.css`.
- React UI-компонент с локальными стилями импортирует colocated `Component.module.css`; logic-only modules не создают пустые stylesheets, глобальный component CSS из React не импортируется.
- Корневой элемент получает `data-theme="light"` или `data-theme="dark"` из theme preference. Компоненты не выбирают palette values в JavaScript и используют только semantic variables.
- Inline `style` допустим только для вычисляемых runtime-величин, например процента progress или координаты drag; неизменяемые visual values остаются в CSS.
- Allowlist дополнительных styling dependencies пуст. Tailwind, Sass/SCSS, CSS-in-JS, отдельная runtime theme library и другие styling packages не входят в MVP; их добавление требует нового решения.

Этот подход опирается на встроенные [scoped styles Astro](https://docs.astro.build/en/guides/styling/#scoped-styles) и [CSS Modules Vite](https://vite.dev/guide/features.html#css-modules), поэтому отдельный styling plugin не требуется.

## Typography

- `IBM Plex Sans` — заголовки, основной текст, controls и feedback; начертания 400, 500, 600 и 700.
- `IBM Plex Mono` — только XP/score, номера миссий, короткие system labels и декоративные цифры Matrix; не использовать для длинных абзацев.
- Основной текст – не меньше 16 CSS px, line-height 1.55–1.7; ширина обычных абзацев не более 70ch согласно более позднему DEC-038. Фактическое число русских букв в строке зависит от текста и метрик шрифта; прежняя формулировка «60–75 символов» не является эквивалентом 70ch и заменена этим измеримым ограничением. Утверждённая геометрия не меняется.
- Uppercase допустим только для коротких system labels; русский текст не набирается сплошными прописными буквами.

## Geometry, surfaces and icons

- Шестигранник — мотив mission nodes, progress markers и отдельных emblem accents, но не форма каждого блока.
- Article и exercise surfaces — прямоугольные панели с radius 8 px; primary controls также имеют radius 8 px. Pill применяется только к коротким status chips.
- Elevation сдержанная: в тёмной теме активное состояние может иметь зелёное/фиолетовое свечение с opacity не выше `0.14`; в светлой — нейтральная тень без neon glow.
- Иконки — единый геометрический line style со stroke 1.5–2 px, без emoji и без текста внутри SVG. Смысловая SVG-графика получает текстовую альтернативу, декоративная скрывается от accessibility tree.

## Matrix background and motion

- Ambient Matrix layer содержит только цифры `0–9`; буквы, псевдокод и случайные символы не используются.
- Это один декоративный неинтерактивный слой: он не содержит статусов, не принимает pointer events и скрыт от accessibility tree.
- За текстом opacity цифр и линий находится в диапазоне `0.04–0.12`; в свободных краевых областях допустимо до `0.18`. Контент располагается на читаемой surface/scrim.
- Потоки движутся медленно и непрерывно с циклами 16–28 секунд; запрещены вспышки, резкая смена яркости, parallax и несколько конкурирующих ambient layers.
- Interaction transitions занимают 120–200 ms; отдельная success animation — 240–400 ms и не задерживает следующий action.
- При `prefers-reduced-motion: reduce` ambient и success motion прекращаются; остаётся статичный низкоконтрастный узор, а вся информация сохраняется текстом и состоянием controls.

## Геймификация в UI

Отображаются:

- XP summary;
- достижения и locked/unlocked state;
- награды;
- прогресс миссий;
- итоговый ранг;
- короткая success animation.

Точные labels, числа и условия утверждены в `DEC-023` и принадлежат spec `04`. Награды остаются косметическими и не блокируют навигацию. Motion не должен задерживать переходы и отключается/сокращается при `prefers-reduced-motion`.

## Responsive

| Контрольная ширина | Ожидаемое поведение |
|---:|---|
| 360 px | Один столбец, touch targets, альтернативы drag-and-drop, без horizontal overflow |
| 768 px | Умеренно широкая статья, карта адаптируется без потери порядка |
| 1440 px | Абзацы ограничены 70ch; интерактивные упражнения могут занимать внешнюю область до 1000px по DEC-038 |

Контрольные ширины не являются единственными breakpoint: layout должен быть fluid между ними.

DEC-038: внешняя область статьи и итогового теста ограничена 1000px. Статья использует отдельную читаемую колонку 70ch для обычного контента; React-упражнения не наследуют это ограничение. MatchPairs включает горизонтальную рабочую область при внутренней ширине от 42rem (не по ширине окна): 2 части текущей ячейке, 3 части описаниям. На меньшей ширине все элементы доступны вертикально. Плотность вложенных рамок описаний уменьшена без изменения палитры и кнопочного пути. Геометрия, отсутствие переполнения и подписи проверяются в `tests/e2e/exercise-layout.spec.ts`.

В этой же проверке при ширине 360px базовый размер текста увеличивается до 200%: документ не шире окна, переключатель светлой темы остаётся доступен. Навигация, кнопки темы и показатели прогресса допускают перенос строк; длинные слова статьи также переносятся. Это проверка увеличенного текста, не замена ручной проверки браузерного масштаба и программ чтения экрана.

## Accessibility contract

- Один логический `h1`, последовательная heading hierarchy.
- Skip link к основному содержимому.
- Нативные buttons, links, radios, checkboxes и inputs, где применимо.
- Focus visible и предсказуем после state transition.
- Status announcements через подходящие live regions.
- Keyboard-only выполнение всех упражнений.
- Touch targets основных controls не меньше 44 × 44 CSS px.
- Drag-and-drop имеет selection + move controls.
- Не использовать motion как единственный носитель информации.
